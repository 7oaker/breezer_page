# Decisions Log

Format: date — decision — why. Append during build; never rewrite history.

A decision belongs here when someone could reasonably have chosen otherwise, and the
reason would not be obvious from reading the code six months later. Record the option
you rejected and why — that is the part that stops the question being reopened.

Status does **not** belong here. What is deployed, what is dirty, how many commits
exist: git, CI and the dashboards know that accurately and this file would not.

---

Entries below were reconstructed on 2026-08-25 from comments already in the source, which
explain their own reasoning unusually well. Each names the file it came from. Dates are
approximate where only the commit history implies them.

- **~2026-07 — EN at the root, DE under `/de/`, `prefixDefaultLocale: false`** — matches the URLs already indexed; prefixing the default locale would have moved every English page. (`astro.config.mjs`)
- **~2026-07 — One `routePairs` map is the single source of truth for EN↔DE** — every hreflang tag, switcher link and sitemap alternate derives from it, so a route can no longer point at a translation that does not exist, which the old string-replacement build allowed. (`src/i18n/routes.ts`)
- **~2026-07 — Frontmatter limits enforced by Zod, not documented as guidance** — a build that fails is the only review step that never gets skipped. `title` caps at 60 because Google rewrites beyond ~600px, and a rewritten title is one you no longer control. (`src/content.config.ts`)
- **~2026-07 — FAQ renders the visible section and the FAQPage schema from one array** — Google requires FAQ schema content to be visible; one source makes drift between them structurally impossible. (`src/content.config.ts`)
- **~2026-07 — Collection IDs generated from `lang/slug`, not the filename** — `en/zyn-tracker.md` and `de/zyn-tracker.md` would otherwise collide and silently overwrite each other. (`src/content.config.ts`)
- **~2026-08 — PostHog runs cookieless and outside the cookie banner** — in `cookieless_mode: 'always'` nothing is written to the visitor's device, so ePrivacy Art. 5(3) (§ 165 TKG 2021 in Austria) is not engaged and no consent is required. Measures 100% of traffic instead of the share who accept the banner. The trade: identity does not survive the daily salt rotation, so a returning visitor counts as new. The banner still gates Google Analytics. (`src/scripts/analytics.js`)
- **~2026-08 — PostHog loaded by dynamic import of the slim build** — an unset `PUBLIC_POSTHOG_KEY` makes the block statically dead, so a static import would have shipped ~250 KB to every visitor even with analytics unconfigured. (`src/scripts/analytics.js`)
- **~2026-08 — `prune-orphan-assets.mjs` runs after every build** — declaring an image via `image()` in a schema makes Astro emit the full-resolution original alongside the optimised variants, ~9.6 MB nothing links to. Only deletes hashed files whose basename appears in no built output. (`scripts/prune-orphan-assets.mjs`)
- **~2026-08 — Shiki emits CSS variables for both themes rather than one baked palette** — the default inline dark-theme colours left formula blocks as near-white text on the light page. (`astro.config.mjs`)
- **~2026-08 — Markdown tables auto-wrapped in a focusable scroll container** — comparison tables are wider than a phone viewport; `tabindex` makes the container keyboard-reachable, which a plain overflow box is not. (`astro.config.mjs`)
- **2026-08-25 — No `llms.txt`** — Google confirmed in June 2026 it affects neither rankings nor AI Overviews. (`.claude/skills/blog-post/references/playbook.md` §9)
- **2026-08-25 — Articles stop at a pull request; merging is publishing** — Vercel deploys from `main`, and the playbook's own rule is that substance, numbers and opinion come from Klaus. Auto-publishing would contradict the document the blog skill is built on. (`.claude/skills/blog-post/SKILL.md` §7)
- **2026-09-07 — The homepage's three app screens are DOM, not screenshots** — the hero's PRESS button, the stats screen and the quit screen were flat PNGs. A picture cannot press, cannot switch period, and cannot tick, which is exactly what each of those three screens exists to prove. Rejected: newer screenshots, which fixes the drift but none of that, and cost ~5.7 MB of PNG. The geometry is a contract, not a guess: the screen box is 261×566 (the frame PNG's window at full size), every source screenshot is 1179×2556 of that same screen, so landmarks map at 261/1179 and the app's type scale at `pt × 261/393`. Sizes in those components are odd pixel values because they were measured; change them by re-measuring. (`src/components/home/AppScreen.astro`)
- **2026-09-07 — The screen is laid out at a fixed 261px and scaled from JS, not sized in container-query units** — `transform: scale(calc(100cqw / 261px))` is valid CSS and works as an inline style, but this project's PostCSS chain drops it before it reaches the browser. A JS-set custom property survives, and the CSS default of `1` is already correct at the 295px the device caps at, so the no-JS path needs no second code path. (`src/scripts/app-screens.js`)
- **2026-09-07 — Layout-critical CSS for slotted or JS-built elements is `:global` or inline, never scoped** — Astro's scoping attribute does not reach elements created in JS, and has twice stopped matching an element that moved through a named slot. Both failures were silent: the bar-chart transition simply never ran, and the hero arrow dropped into normal flow below the phone. Anything positioning or animating those elements is deliberately outside the scoped selector. (`src/components/home/StatsPhone.astro`, `PressPhone.astro`)
- **2026-09-07 — The quit screen's leaderboard uses invented names** — the source screenshot shows real Breezer users, two with country flags, plus a real account name in the congratulations line. Publishing those would put real people on a public marketing page without their consent. Day counts and the sampled avatar colours are kept. (`src/components/home/QuitPhone.astro`)
- **2026-09-07 — The mockups deviate from the app in four named places, and only these** — the press cooldown is 9s rather than 15min (a literal copy gives a visitor one press and then a dead grey circle); the stats donut and total animate where the app swaps them instantly (against bars that take most a second, an instant arc reads as a glitch); the period selector cycles itself every 3s until someone touches it; and under reduced motion the quit clock does not tick at all, because a number changing every second is what that preference asks to be spared. Everything else — colours, strings, stat formulas, the 4s breathe — is copied from `react_Breezer` verbatim so the two cannot drift. (`src/scripts/press-phone.js`, `stats-phone.js`, `quit-phone.js`)
- **2026-09-07 — A pointing hand replaces the mouse pointer over the rebuilt app screens** — the three screens are operable but read as pictures, and a hand reaching for the PRESS button says "this one is real" before anything is clicked. One element for the whole page, bound to every `[data-app-screen]`, because there is only ever one pointer. Rejected: `cursor: url(...)`, which is the obvious way and cannot work here, since browsers cap a CSS cursor at 128x128 and the artwork is a 640x1130 arm. Mouse only (`hover: hover and pointer: fine`): on a phone the hand would appear under the finger already covering the button. It tracks the pointer even under reduced motion, because that movement is the visitor's own; only the fade and the press squash sit inside the no-preference query. (`src/components/home/AppHandCursor.astro`, `src/scripts/app-screens.js`)
- **2026-09-07 — The hand lives on `document.body`, not inside the component that renders it** — `position: fixed` resolves against the nearest transformed ancestor, and the hero device sits inside both `float-slow` and a `.wow` reveal whose animation leaves a transform behind, either of which would trap the hand and make it track the wrong origin. The script reparents it on init. Its hotspot (16.33% of the image width, top row) was measured off the source PNG and is both the offset and the `transform-origin`, so a press closes the hand toward the button instead of sliding it off. (`src/components/home/AppHandCursor.astro`)
- **2026-09-08 — The homepage's feature icons are Lucide, not Material Symbols Filled** — the nine icons in `Icon.astro` were Material Symbols in the Filled style, which is the solid-blob look, and they sit a few hundred pixels from three rebuilt app screens whose chrome is drawn as 2px stroked line icons. One page cannot speak two icon languages that far apart, and the filled set was the older-looking half. Rejected: Material Symbols Outlined, which is the smaller change (same family, same keys, same Apache-2.0 note) but still reads as a different system next to the phones. The keys still name the slot rather than the glyph, so which icon a feature draws is a change in that one file. Three of the nine were also near-identical bar charts (Tracking, Ranking, Quitting Statistics); the swap took the chance to give Ranking a trophy and Promotions a discount ticket. (`src/components/Icon.astro`)
- **2026-09-16 — The community numbers are fetched at build time, not in the browser** — one public Appwrite row, written weekly by `functions/community-stats` in the app repo, read once per build and baked into the HTML. Rejected: a fetch on page load, which costs an Appwrite read per visitor, ships another request before the numbers appear and makes them land late into a settled layout. Also rejected: an Appwrite API key in the Vercel build environment, because Appwrite key scopes are project wide, so a `documents.read` key there would read the user table and its e-mail addresses too; the row is world readable instead and holds nothing but community totals. The fetch is memoised, so 41 pages cost one request. (`src/data/communityStats.ts`)
- **2026-09-16 — A row that cannot be read renders nothing, and there is no fallback snapshot** — a hardcoded set of numbers would survive an outage, and would also be exactly the stale invented figure this whole mechanism exists to replace. The build stays green either way, the band simply does not appear. (`src/components/home/CommunityStats.astro`)
- **2026-09-16 — Three of the five figures keep counting between builds** — the row carries a per-day rate next to days, pouches and money, because the app's savings formula is linear in time, so the browser can carry them forward exactly from `computedAt`. That is what lets the source job run weekly instead of nightly. The server-rendered value is already projected to build time, so a visitor without JavaScript sees a correct number, just an older one. The ticking interval starts up front rather than from the count-up's callback: `requestAnimationFrame` does not run in a background tab, and hanging the real behaviour off a frame that may never arrive left a page opened in a background tab showing the build-time value forever. The count-up also measures with `performance.now()` rather than the frame timestamp it is handed, because after a spell in the background that timestamp can predate the animation and a negative progress painted every figure as a minus number. (`src/scripts/community-stats.js`)
- **2026-09-16 — One page carries free and Pro, and it names the prices** — `/pricing` and `/de/preise` are one page in two languages, not a free page and a Pro page, because both would answer the same question and compete for it. It is deliberately not an SEO page: the entire price-and-free corner produces six queries in 180 days, the largest at two impressions, so anything built to rank there would be a thin page on absent demand. It exists for expectation and citability — the app presents a paywall at the end of onboarding and has fifteen real gates, and "is it free" is a question that now goes to assistants rather than to Google. The order of the sections is the argument: what is free comes before what Pro adds, and the limits come after the price, because the generosity is only credible with the limits printed next to it. Rejected: leaving it at the homepage FAQ answer, which scatters the answer and gives nothing a URL. (`src/content/guides/{en/pricing.md,de/preise.md}`)
- **2026-09-16 — The prices are hardcoded on that page, with the drift named rather than avoided** — €2.99 monthly and €19.99 yearly, one free week, checked against App Store Connect on 16.09.2026. No repo holds these numbers: the app reads them from RevenueCat at runtime, which reads them from the stores, and there are three offerings (`tracking`, `quitting`, Current) that can carry different packages. Rejected: printing no amount and arguing only relatively, which is safe and drops the argument Klaus wants; and deriving them at build time, which would need store credentials in the build for a number that changes once a year. The mitigation is a comment at the top of both files naming the source and the date, and the rule that a price change touches both language versions in the same commit. (`src/content/guides/en/pricing.md`)
- **2026-09-16 — The quit guides now mark which health milestones need Pro** — the table presented days 1 to 90 as "what the app shows", but `FREE_IMP_COUNT = 4` in the app means days 30 and 90 are Pro, as is most of the journey. A marketing page that shows paid content as included is the same broken promise as the paywall after onboarding, one step earlier. (`src/content/guides/en/quit-snus.md`, `src/content/guides/de/snus-aufhoeren.md`)
- **2026-09-17 — The screenshot carousels rotate by themselves until somebody touches them** — standing still, they showed three of eleven tracking screenshots to every visitor who never reached for an arrow. Four seconds a screen, hover pauses, and a swipe, an arrow click or the keyboard reaching an arrow stops it for good, which is also what satisfies WCAG 2.2.2 (moving content over five seconds needs a way to stop it); under `prefers-reduced-motion` nothing moves at all. Rejected: a timer of our own beside Swiper, since Swiper's Autoplay module already knows the loop, waits for the transition to finish and handles the hover pause. Also rejected: its `pause()` for the off-screen and background-tab gate, because pausing leaves the requestAnimationFrame loop that counts the delay down running and only `stop()` cancels it. The visitor's takeover is remembered outside Swiper, in a `taken` flag, because `disableOnInteraction` stops the instance without remembering it and the gate calls `start()` again on every return to the screen. The same bargain the stats screen's period selector makes. (`src/scripts/main.js`, `src/scripts/stats-phone.js`)
- **2026-09-17 — The Pro page ends on a founder's note, in the first person** — the page said what Pro costs and where the free version stops, and answered "why is there a price at all" in one half-width card that only said the app costs more to run than it earns. That card is now a section: infrastructure and services cost money every month, the difference comes out of Klaus's pocket, the order of the goals is cover the costs, then buy time for the project, then bigger drops, giveaways and partner cooperations so money out of the community ends up back in it. It closes on the honest part, that he has used snus for years himself and does not know whether that is good or bad, which is also the reason the app counts and helps in the same build. First person and signed by an eyebrow rather than the site's voice: a price defended by a company reads as a policy, one defended by a person reads as a reason. Rejected: itemising the costs and naming the 15 to 30 percent the stores take, because no number of that kind is derivable from either repo and the store line reads as blaming Apple and Google for the price. Also rejected: keeping the old card and adding the section, which would leave two places half-answering the same question. The same question is now also an FAQ entry, so it sits in the page's FAQPage schema where an assistant looks for it. (`src/components/Pricing.astro`, `src/i18n/pricing.ts`)
- **2026-09-17 — The Pro page rebuilds the app's referral counter instead of describing it** — "invite three friends" was a sentence; it is now the widget from `react_Breezer/components/homecards/ReferralSection.jsx`, three segments for the threshold of three, with that screen's own three steps under it. Rebuilt in DOM rather than screenshotted, and in the site's palette apart from the filled segments, which keep the app's #1FD9FF because that is the one element the app itself paints in it: a dark app card dropped into a light page reads as a pasted screenshot, and a gradient across a 2px bar reads as two different fills across three segments. On the light page that bar is quiet against white, which is why the state is also carried in words by the counter beside it. Nobody is signed in on a marketing page, so the counter is an explanation and not a status: it starts empty, fills once when it scrolls into view, stops at three with the reward step ticked, and a caption says where the real one lives. Rejected: leaving it at a static zero of three, which is honest and explains nothing, and a static two of three, which claims a count the visitor does not have. It runs once because the sheen over the Pro card does, and for the same reason: on this page movement is emphasis, and anything that loops is decoration. (`src/components/Pricing.astro`, `src/scripts/main.js`)
- **2026-09-17 — The device frame is painted as a CSS background, not rendered as an `<img>`** — `mobile-frame.png` was five separate `<img>` elements on the home page, more than any other image there, and Google Images indexed it on its own: a transparent PNG flattened onto white, so the result was an empty white phone carrying the page's title and favicon. `/de` was the landing page Google happened to attach it to; both languages reference the same hashed file, so which one it picks is arbitrary. `og:image` has no bearing on this — Google Images indexes every `<img>` on a page independently, which is why the share previews looked fine the whole time. Rejected: `noimageindex`, which would have taken the sixteen app screenshots down with it, and those are the images that should rank. Also rejected: a `robots.txt` disallow on the hashed filename, which breaks the moment the asset changes and its hash moves. A CSS background is not indexed at all, and the frame is decorative, so it belongs in one. `getImage()` gives the same optimised variant `<Image>` would have emitted, and the URL appears in the built HTML, so `prune-orphan-assets.mjs` still sees it referenced. (`src/components/PhoneFrame.astro`, `src/components/home/ScreenCarousel.astro`)
