# Decisions Log

Format: date — decision — why. Append during build; never rewrite history.

A decision belongs here when someone could reasonably have chosen otherwise, and the
reason would not be obvious from reading the code six months later. Record the option
you rejected and why — that is the part that stops the question being reopened.

Status does **not** belong here. What is deployed, what is dirty, how many commits
exist: git, CI and the dashboards know that accurately and this file would not.

---

Entries below were reconstructed on 2026-08-25 from comments already in the source, which
explain their own reasoning unusually well. Each names the file it came from. Dates are
approximate where only the commit history implies them.

- **~2026-07 — EN at the root, DE under `/de/`, `prefixDefaultLocale: false`** — matches the URLs already indexed; prefixing the default locale would have moved every English page. (`astro.config.mjs`)
- **~2026-07 — One `routePairs` map is the single source of truth for EN↔DE** — every hreflang tag, switcher link and sitemap alternate derives from it, so a route can no longer point at a translation that does not exist, which the old string-replacement build allowed. (`src/i18n/routes.ts`)
- **~2026-07 — Frontmatter limits enforced by Zod, not documented as guidance** — a build that fails is the only review step that never gets skipped. `title` caps at 60 because Google rewrites beyond ~600px, and a rewritten title is one you no longer control. (`src/content.config.ts`)
- **~2026-07 — FAQ renders the visible section and the FAQPage schema from one array** — Google requires FAQ schema content to be visible; one source makes drift between them structurally impossible. (`src/content.config.ts`)
- **~2026-07 — Collection IDs generated from `lang/slug`, not the filename** — `en/zyn-tracker.md` and `de/zyn-tracker.md` would otherwise collide and silently overwrite each other. (`src/content.config.ts`)
- **~2026-08 — PostHog runs cookieless and outside the cookie banner** — in `cookieless_mode: 'always'` nothing is written to the visitor's device, so ePrivacy Art. 5(3) (§ 165 TKG 2021 in Austria) is not engaged and no consent is required. Measures 100% of traffic instead of the share who accept the banner. The trade: identity does not survive the daily salt rotation, so a returning visitor counts as new. The banner still gates Google Analytics. (`src/scripts/analytics.js`)
- **~2026-08 — PostHog loaded by dynamic import of the slim build** — an unset `PUBLIC_POSTHOG_KEY` makes the block statically dead, so a static import would have shipped ~250 KB to every visitor even with analytics unconfigured. (`src/scripts/analytics.js`)
- **~2026-08 — `prune-orphan-assets.mjs` runs after every build** — declaring an image via `image()` in a schema makes Astro emit the full-resolution original alongside the optimised variants, ~9.6 MB nothing links to. Only deletes hashed files whose basename appears in no built output. (`scripts/prune-orphan-assets.mjs`)
- **~2026-08 — Shiki emits CSS variables for both themes rather than one baked palette** — the default inline dark-theme colours left formula blocks as near-white text on the light page. (`astro.config.mjs`)
- **~2026-08 — Markdown tables auto-wrapped in a focusable scroll container** — comparison tables are wider than a phone viewport; `tabindex` makes the container keyboard-reachable, which a plain overflow box is not. (`astro.config.mjs`)
- **2026-08-25 — No `llms.txt`** — Google confirmed in June 2026 it affects neither rankings nor AI Overviews. (`.claude/skills/blog-post/references/playbook.md` §9)
- **2026-08-25 — Articles stop at a pull request; merging is publishing** — Vercel deploys from `main`, and the playbook's own rule is that substance, numbers and opinion come from Klaus. Auto-publishing would contradict the document the blog skill is built on. (`.claude/skills/blog-post/SKILL.md` §7)
- **2026-09-07 — The homepage's three app screens are DOM, not screenshots** — the hero's PRESS button, the stats screen and the quit screen were flat PNGs. A picture cannot press, cannot switch period, and cannot tick, which is exactly what each of those three screens exists to prove. Rejected: newer screenshots, which fixes the drift but none of that, and cost ~5.7 MB of PNG. The geometry is a contract, not a guess: the screen box is 261×566 (the frame PNG's window at full size), every source screenshot is 1179×2556 of that same screen, so landmarks map at 261/1179 and the app's type scale at `pt × 261/393`. Sizes in those components are odd pixel values because they were measured; change them by re-measuring. (`src/components/home/AppScreen.astro`)
- **2026-09-07 — The screen is laid out at a fixed 261px and scaled from JS, not sized in container-query units** — `transform: scale(calc(100cqw / 261px))` is valid CSS and works as an inline style, but this project's PostCSS chain drops it before it reaches the browser. A JS-set custom property survives, and the CSS default of `1` is already correct at the 295px the device caps at, so the no-JS path needs no second code path. (`src/scripts/app-screens.js`)
- **2026-09-07 — Layout-critical CSS for slotted or JS-built elements is `:global` or inline, never scoped** — Astro's scoping attribute does not reach elements created in JS, and has twice stopped matching an element that moved through a named slot. Both failures were silent: the bar-chart transition simply never ran, and the hero arrow dropped into normal flow below the phone. Anything positioning or animating those elements is deliberately outside the scoped selector. (`src/components/home/StatsPhone.astro`, `PressPhone.astro`)
- **2026-09-07 — The quit screen's leaderboard uses invented names** — the source screenshot shows real Breezer users, two with country flags, plus a real account name in the congratulations line. Publishing those would put real people on a public marketing page without their consent. Day counts and the sampled avatar colours are kept. (`src/components/home/QuitPhone.astro`)
- **2026-09-07 — The mockups deviate from the app in four named places, and only these** — the press cooldown is 9s rather than 15min (a literal copy gives a visitor one press and then a dead grey circle); the stats donut and total animate where the app swaps them instantly (against bars that take most a second, an instant arc reads as a glitch); the period selector cycles itself every 3s until someone touches it; and under reduced motion the quit clock does not tick at all, because a number changing every second is what that preference asks to be spared. Everything else — colours, strings, stat formulas, the 4s breathe — is copied from `react_Breezer` verbatim so the two cannot drift. (`src/scripts/press-phone.js`, `stats-phone.js`, `quit-phone.js`)
- **2026-09-07 — A pointing hand replaces the mouse pointer over the rebuilt app screens** — the three screens are operable but read as pictures, and a hand reaching for the PRESS button says "this one is real" before anything is clicked. One element for the whole page, bound to every `[data-app-screen]`, because there is only ever one pointer. Rejected: `cursor: url(...)`, which is the obvious way and cannot work here, since browsers cap a CSS cursor at 128x128 and the artwork is a 640x1130 arm. Mouse only (`hover: hover and pointer: fine`): on a phone the hand would appear under the finger already covering the button. It tracks the pointer even under reduced motion, because that movement is the visitor's own; only the fade and the press squash sit inside the no-preference query. (`src/components/home/AppHandCursor.astro`, `src/scripts/app-screens.js`)
- **2026-09-07 — The hand lives on `document.body`, not inside the component that renders it** — `position: fixed` resolves against the nearest transformed ancestor, and the hero device sits inside both `float-slow` and a `.wow` reveal whose animation leaves a transform behind, either of which would trap the hand and make it track the wrong origin. The script reparents it on init. Its hotspot (16.33% of the image width, top row) was measured off the source PNG and is both the offset and the `transform-origin`, so a press closes the hand toward the button instead of sliding it off. (`src/components/home/AppHandCursor.astro`)
